Randomized Algorithms

CS F364 — Design & Analysis of Algorithms | Summer 2026

Las Vegas vs Monte Carlo, Freivalds’ algorithm, error reduction, probability basics, expected runtime

← Practice

NoteProblem E1

Distinguish Las Vegas and Monte Carlo randomized algorithms. Give one example of each type from the course.

TipSolution

Las Vegas: always correct, randomized runtime (e.g., randomized quicksort). Monte Carlo: bounded error, deterministic runtime (e.g., Freivalds’ algorithm).

NoteProblem E2

Let x \in \{0,1\}^n be a non-zero vector and let r \in \{0,1\}^n be chosen uniformly at random. Show that \Pr[\langle r, x \rangle = 0 \pmod{2}] \le 1/2.

Now use this to analyze Freivalds’ algorithm: to check AB = C, pick r \in \{0,1\}^n uniformly and check A(Br) = Cr. If AB \neq C, what is the maximum probability that the test passes (false positive)?

TipSolution

For \langle r, x \rangle = \sum_{i=1}^n r_i x_i \pmod{2} to be 0, an even number of positions where x_i = 1 must have r_i = 1. Pick any j with x_j = 1. Condition on all r_i for i \neq j. Then \langle r, x \rangle flips with r_j: exactly one choice of r_j \in \{0,1\} makes the sum 0. So \Pr[\langle r, x \rangle = 0] = 1/2.

For Freivalds: if AB \neq C, then D = AB - C \neq 0 is a non-zero matrix. The test passes if Dr = 0. Since D \neq 0, there is at least one non-zero row. For a non-zero row d \neq 0, \Pr[d \cdot r = 0] \le 1/2 by the lemma, so \Pr[Dr = 0] \le 1/2.

NoteProblem E3

You run Freivalds’ algorithm once and it says AB = C. What can you conclude? If it says AB \neq C, what can you conclude? Now suppose you run the test k times independently and it passes every time. What is the probability of error after k runs? How many runs are needed to achieve error < \epsilon?

TipSolution

If the test passes, AB = C with probability at least 1/2 (one-sided error: false positives possible). If it fails, AB \neq C with certainty (no false negatives). After k independent passes, error \le (1/2)^k. For error < \epsilon, need k > \log_2(1/\epsilon).

NoteProblem E4

Consider the following Monte Carlo algorithm: to check if an array A[1..n] has a majority element, pick a random index i and check whether A[i] appears more than n/2 times in A.

  1. If a majority element exists, what is the probability that one random pick finds it?
  2. How many independent picks are needed to find a majority element with probability at least 1 - \delta?
  3. Is this a Las Vegas or Monte Carlo algorithm? Justify.
TipSolution
  1. If a majority element exists, it occupies > n/2 positions. Probability a random pick hits it: > (n/2)/n = 1/2.
  2. With k independent picks, failure probability (never picking the majority) < (1/2)^k. To get failure < \delta, need k > \log_2(1/\delta).
  3. Monte Carlo — the algorithm has one-sided error: if it returns an element, that element is guaranteed majority (after verification), but it may fail to find one even if it exists.
NoteProblem E5

Let A[1..n] be an array of n distinct numbers. Consider randomized quickselect: pick a uniformly random pivot, partition, and recurse on the side containing the k-th smallest element.

  1. What is the probability that a random pivot gives a “good split” (splits the array into two parts each of size at most 3n/4)?
  2. Using this, bound the expected number of recursive calls.
  3. How does the expected runtime compare to the worst-case runtime?
TipSolution
  1. A good split occurs when the pivot is not in the smallest n/4 nor the largest n/4 elements. Probability = 1/2.
  2. Each good split reduces the problem to at most 3n/4 size. Expected number of picks until a good split = 2 (geometric with p=1/2). So expected calls before size reduces: 2. Total expected depth: O(\log n).
  3. Expected runtime O(n) (each level processes O(n) elements across all calls). Worst-case runtime O(n^2) (adversarial pivot choices).
NoteProblem E6

You flip a fair coin repeatedly. Let X be the number of flips until you see heads for the first time.

  1. What is the distribution of X? Compute \Pr[X = k] for k \ge 1.
  2. Compute \mathbb{E}[X] using linearity of expectation or the tail-sum formula.
  3. Now let Y be the number of heads in n independent flips. What is \mathbb{E}[Y]? How does this illustrate linearity of expectation?
TipSolution
  1. X \sim \text{Geometric}(1/2): \Pr[X = k] = (1/2)^{k-1} \cdot (1/2) = (1/2)^k.
  2. \mathbb{E}[X] = \sum_{k=1}^\infty \Pr[X \ge k] = \sum_{k=1}^\infty (1/2)^{k-1} = 2. Or using tail sum: \mathbb{E}[X] = \sum_{k=0}^\infty \Pr[X > k] = \sum_{k=0}^\infty (1/2)^k = 2.
  3. Y = \sum_{i=1}^n I_i where I_i \sim \text{Bernoulli}(1/2). By linearity, \mathbb{E}[Y] = \sum_{i=1}^n \mathbb{E}[I_i] = n \cdot 1/2 = n/2, even though the I_i are independent.
NoteProblem E7

A Monte Carlo algorithm for a decision problem has one-sided error: it is always correct when it says “yes”, but may err when it says “no” (false negatives). Suppose on a “no” instance, it incorrectly says “yes” with probability at most 1/2.

  1. If the algorithm says “no” once, what can you conclude?
  2. If it says “yes” once, what can you conclude?
  3. How many independent runs (all saying “yes”) are needed to guarantee error < \epsilon?
  4. Generalize: if the one-sided error probability is at most p, how many runs are needed?
TipSolution
  1. If “no”, then the answer is definitely “no” (no false negatives).
  2. If “yes”, then it could be correct or a false positive — the answer is “yes” with confidence at least 1/2.
  3. After k independent runs all saying “yes”, error \le (1/2)^k. Need k > \log_2(1/\epsilon).
  4. With error \le p per run, after k runs all saying “yes”, error \le p^k. Need k > \log_{1/p}(1/\epsilon).
NoteProblem E8

You are given an unbiased coin. Design a randomized algorithm that uses this coin to simulate a biased coin that lands heads with probability exactly 1/3. What is the expected number of flips your algorithm uses per output?

TipSolution

Flip the coin twice. Map: HH \to H, HT \to T, TH \to T, TT \to repeat. \Pr[H] = 1/4 conditioned on not repeating, but we need exactly 1/3. Alternative: flip until you get HT or TH, then output H for HT and T for TH. Each of HT and TH has probability 1/4, so conditioned on stopping, each has probability 1/2. Not 1/3.

Correct method: flip until you see HHT or HTH or THH. Map HHT \to H, HTH \to H, THH \to T, and repeat on other outcomes. Each of the 3 patterns has probability 1/8 conditioned on one of them occurring, so \Pr[H] = 2/3 not 1/3.

Simpler: flip twice. If HH \to H, if HT or TH \to T, if TT \to repeat. \Pr[H] = 1/4 and \Pr[T] = 1/2, so conditioned on not repeating, \Pr[H] = (1/4)/(3/4) = 1/3. Expected flips per output: each trial uses 2 flips and succeeds with probability 3/4, so expected flips = 2 / (3/4) = 8/3.
