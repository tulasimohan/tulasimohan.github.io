Design and Analysis of Algorithms

Huffman Coding

Encoding and Decoding Problem

Suppose we have a \(100000\) character data file that we want to store. The file contains only \(6\) characters with the following frequencies:

  • A binary code encodes each character as a binary string.

  • We want to find a binary code that encodes the file using as few bits as possible. In other words, we want to compress the file as much as possible.

Encoding and Decoding Problem

  • Fixed length code: Each codeword has the same length.

  • Variable length code: Codewords may have different length.

  • Example:

  • Fixed length code requires \(300,000\) bits to store the file.

  • Number of bits required to store the file using variable length code is: \((45\cdot 1 + 13\cdot 3 + 12\cdot 3 + 16\cdot 3 + 9\cdot 4 + 5\cdot 4)\cdot 1000 = 224,000\) bits.

  • Saving using variable length code is around \(25\%\).

  • In what follows a code is a set of codewords, e.g, \(\{000, 001, 010, 011, 100, 101\}\) and \(\{0, 101, 100, 111, 1101, 1100\}\).

Encoding

Given a code corresponding to some alphabet \(\Gamma\) and a message, it is easy to encode the message by replacing the characters with codewords. For example, let \(\Gamma = \{a,b,c,d\}\).

  • Suppose the code is \(C_1: \{a=00, b=01, c=10, d=11\}\). Encoding of “bad" using \(C_1\) is 010011.

  • Suppose the code is \(C_2: \{a=0, b=110, c=10, d=111\}\). Encoding of “bad" using \(C_2\) is 1101111.

  • Suppose the code is \(C_3: \{a=1, b=110, c=10, d=111\}\). Encoding of “bad" using \(C_3\) is 1101111.

Decoding

Given an encoded message, decoding is the process of retrieving the original message. A message is uniquely decodable if it can only be decoded in one way.

  • Relative to \(C_1\), 010011 is uniquely decodable to “bad".

  • Relative to \(C_2\), 1101111 is uniquely decodable to “bad".

  • Relative to \(C_3\), 1101111 is not uniquely decodable. It can be decoded to either “bad" or”acad".

Prefix-Codes

  • Fixed length codes are always uniquely decodable (Why?).

  • Fixed length codes do not provide best compression!

  • Prefix Code: A code is called prefix code if no codeword is a prefix of one another.

  • Every message encoded by a prefix code is uniquely decodable. Since no codeword is a prefix of the other, we can always find the first codeword, peel it off, and continue decoding.

  • Goal: Find a good prefix code.

Optimal Source Coding

The Problem: Given an alphabet \(A=\{a_1, a_2, ..., a_n\}\) with frequency distribution \(f(a_i)\), find a binary prefix code \(C\) for \(A\) that minimizes the number of bits: \(B(C) = \sum_{i=1}^{n}f(a_i)L(c(a_i))\) needed to encode a message of \(\sum_{i=1}^{n}f(a_i)\) characters, where \(c(a_i)\) is the codeword for encoding \(a_i\) and \(L(c(a_i))\) is the length of the codeword \(c(a_i)\).

Huffman Coding

Huffman developed a nice greedy algorithm for solving this problem. The code that the greedy algorithm produces is called a Huffman code.

Huffman Coding

Step-1: Pick two letters \(x\) and \(y\) from alphabet \(A\) with the smallest frequencies and create a subtree that has these two characters as leaves. ( Greedy idea). Label the root of this subtree as \(z\).
Step-2: Set frequency \(f(z) = f(x)+f(y)\). Remove \(x, y\) and add \(z\) creating new alphabet \(A' = A\cup\{z\}-\{x,y\}\).
Repeat this procedure, called merge, with new alphabet \(A'\) until an alphabet with only one symbol is left.
The resulting tree is the Huffman code.

Analysis

Let \(T\) be an optimal code tree. Then \(T\) is a full binary tree. In particular, if the height of \(T\) is \(d\), then there are leaf nodes of height \(d\) that are sibling.

Proof. Proof. If there is an internal node in \(T\) that has one child, we can remove this node from \(T\), by connecting its only child directly with its parent. The resulting code tree is clearly a better compressor.

As for the second claim, consider a leaf \(u\) with max depth \(d\) in \(T\), and consider its parent \(v\). The node \(v\) has two children, and they are both leaves (otherwise \(u\) is not the deepest node in the tree), as claimed. ◻

Greedy Choice Property

Let \(x\) and \(y\) be the two least frequent characters. There is an optimal code tree in which \(x\) and \(y\) are siblings.

Proof. Proof. Idea: Let \(T\) represents an arbitrary optimal prefix-free code. We can show that \(T\) can be modified to another optimal prefix-free code tree \(T'\) such that \(x\) and \(y\) appear as siblings at the maximum depth of \(T'\). ◻

Greedy Choice Property

Proof. Proof. \[\begin{aligned} B(T) - B(T'') &= f(x)d_{T}(x) + f(y)d_{T}(y) + f(a)d_{T}(a) + f(b)d_{T}(b) - \\ & (f(x)d_{T''}(x) + f(y)d_{T''}(y) + f(a)d_{T''}(a) + f(b)d_{T''}(b)) \\ &= f(x)d_{T}(x) + f(y)d_{T}(y) + f(a)d_{T}(a) + f(b)d_{T}(b) - \\ & (f(x)d_{T}(a) + f(y)d_{T}(b) + f(a)d_{T}(x) + f(b)d_{T}(y)) \\ &= (f(a)-f(x))(d_T(a)-d_T(x)) + (f(b)-f(y))(d_T(b) - d_T(y)) \\ &>= 0. \end{aligned}\] Thus, \(B(T) = B(T'')\). ◻
