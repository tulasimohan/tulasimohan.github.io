Prim’s Algorithm

In this algorithm, we start with a node and grow an MST out of it.

We start with an arbitrary node \(u\) and include it in \(T\). We then find the lowest-weight edge incident on \(u\) and add this to \(T\). We then repeat, always adding the minimum-weight edge that has exactly one endpoint in \(T\) to \(T\). Formal description of the algorithm is as follows:

  1. Pick some arbitrary start node \(u\). Initialize \(T=\{u\}\).

  2. Repeatedly pick the lowest-weight edge incident to \(T\) that has exactly one vertex is in \(T\) until \(T\) spans all nodes.

Correctness of Prim’s Algorithm

Prim’s algorithm correctly computes an MST

Proof. Proof. We’ll prove this by induction. The induction hypothesis will be that after each iteration, the tree \(T\) is a subgraph of some minimum spanning tree \(M\). This is trivially true at the start, since initially \(T\) is just a single node and no edges. Now suppose that at some point in the algorithm we have \(T\) which is a subgraph of \(M\), and Prim’s algorithm tells us to add the edge \(e\). So we need to prove that \(T\cup\{e\}\) is also a subtree of some MST. If \(e\in M\) then this is clearly true, since by induction \(T\) is a subtree of \(M\) and \(e\in M\) and thus \(T\cup\{e\}\) is a subtree of \(M\). ◻

Second part of the proof is similar to Kruskal’s proof.

Time Complexity

How do we find the cheapest edge with exactly one endpoint in \(T\)?

  • Approach-1: Brute force: try all edges. \(O(E)\) time per edge finding. \(O(EV)\) time overall.

  • Approach-2: Maintain vertices in a Priority Queue (PQ) based on the weights of the least cost incident edge.

    1. Delete min to determine the next edge \(e\) (incident to the corresponding vertex) to add to \(T\).

    2. Discard \(e\) if both the endpoints are in \(T\).

    3. Once \(e\) is added, update the weights of the least cost edges incident to the vertex added to \(T\).

    4. \(O(\log{V})\) cost for extract min and decrease key. The overall cost is therefore \(O(V\log{V} + E\log{V}) = O(E\log{V})\).

Boruvka’s Algorithm

  • Invented in 1926 by a Czech mathematician Otakar Boruvka (1899 - 1995). he is best known for his work in graph theory.

  • He designed this algorithm to solve a electrical network problem in Moravia.

  • This algorithm is more suitable for distributed and parallel computation.

  • This algorithm plays a pivotal role in a randomized linear time algorithm for MST due to Karger, Klein, and Tarjan (1995).

Boruvka’s Algorithm

  1. Start by creating a set \(S(v) = \{v\}\) for each vertex \(v\in V\) and an empty subgraph \(T=\phi\) initially.

  2. In each round

    1. For each set \(S\), find the minimum weight edge going out of \(S\), i.e, min\(\{w(u,v)| u\in S, v\notin S\}\). Let \(e_S\) be the edge computed for the set \(S\).

    2. Add every edge \(e_S=(u,v)\) to the subgraph \(T\) and merge the sets of \(S(u)\) and \(S(v)\) into a single set \(S\).

  3. Repeat the rounds until all vertices are merged into a single set and return \(T\).

Correctness Proof

  • Any edge added by the algorithm in a round connects two different connected components.

  • What if the edges added in the same round form a cycle?This cannot happen because the weight of the picked edges in any path should be strictly decreasing. Thus, the edges cannot form a cycle. So, \(T\) is a tree.

  • By the cut rule, any edge inserted by the algorithm is the minimum weight edge going out of the connected component.

Time Complexity

  • Each round of the algorithm takes \(O(m)\) time as it involves going over all edges of the graph twice (one from each endpoint).

  • In each round, each connected component gets merged with at least one another, and thus the number of components decreases by, at least, a factor of two. So, after at most \(\log{n}\) rounds, only one component remains.

  • Thus, the overall time complexity is \(O(m\log{n})\).

Exchange Argument

  1. Greedy algorithm generally take the following form:

    • Select a candidate greedily according to some heuristic, and add it to your current solution if doing so doesn’t corrupt feasibility.

    • Repeat if not finished.

  2. “Greedy Exchange" is one of the techniques used in proving the correctness of greedy algorithms.

    • The idea is to incrementally modify a solution produced by any other algorithm into the solution produced by your greedy algorithm in a way that doesn’t worsen the solution’s quality.

    • Thus the quality of your solution is at least as great as that of any other solution.

    • Thus, your algorithm does in fact return an optimal solution.
