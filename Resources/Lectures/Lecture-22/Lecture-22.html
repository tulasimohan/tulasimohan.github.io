Design and Analysis of Algorithms

Amortized analysis

Multipop stack

Multipop stack

Goal: Support operations on a set of elements:

  • PUSH\((S, x):\) add element \(x\) to stack \(S\).

  • POP\((S):\) remove and return the most-recently added element.

  • MULTI-POP\((S, k):\) remove the most recently added \(k\) elements.

Multipop stack

  • PUSH and POP can be implemented in \(O(1)\) time.

  • MULTI-POP\((S, k)\) can be implemented in \(O(k)\) time.

  • Consider a sequence of \(n\) PUSH, POP, MULTI-POP:

    • Total number of operations is \(n\).

    • The \(n\) operations can be a mix of PUSH, POP, MULTI-POP

  • A simple time complexity analysis:

    • The worst case time for MULTI-POP in the sequence is \(O(n)\), since the stack size is at most \(n\).

    • Hence the worst case time of the sequence is \(O(n^2)\).

  • This is correct, but a loose bound.

    • An obvious issue: All \(n\) operations cannot be MULTI-POP!

Amortized analysis: aggregate method

  • Consider a sequence of \(n\) PUSH, POP, MULTI-POP operations on an initially empty stack.

  • MULTI-POPs are nothing but a sequence of POPs, so analysis can consider only number of PUSH and POPs (either direct POP or POPs within a MULTI-POP).

  • Each element pushed can be popped at most once.

  • So the no. of POP operations (including POPs within a MULTI-POP) \(\leq\) number of PUSH operations.

  • Thus the total time is at most \(O(n)\) since PUSH and POP are \(O(1)\) each.

  • Hence the average cost of operation is \(O(n)/n = O(1)\).

  • We say that the amortized cost of a PUSH, POP, or MULTI-POP in a sequence of \(n\) operations in \(O(1)\).

Amortized analysis: accounting method

Credits: \(1\) credit pays for either a PUSH or POP.
Invariant: Every element on the stack has \(1\) credit.
Accounting:

  • PUSH\((S, x):\) charge \(2\) credits.

    • use \(1\) credit to pay for pushing \(x\) now.

    • store \(1\) credit to pay for popping \(x\) at some point in the future.

  • POP\((S):\) charge \(0\) credits.

  • MULTI-POP\((S, k):\) charge \(0\) credits.

Amortized analysis: accounting method

Starting from an empty stack, any intermixed sequence of \(n\) PUSH, POP, and MULTI-POP operations takes \(O(n)\) time.

Proof. Proof.

  • Number of credits in datastructure \(\geq 0\).

  • Amortized cost per operation \(\leq 2\).

  • Total actual cost of \(n\) operations \(\leq\) sum of amortized costs \(\leq 2n\)

 ◻

Amortized analysis: potential method

Potential function: Let \(\Phi(D) =\) number of elements currently on the stack.

  • \(\Phi(D_0) = 0\).

  • \(\Phi(D_i)\geq 0\) for each \(D_i\).

Amortized costs:

  • PUSH

    • Potential change = \((|S|+1) - |S| = 1\).

    • Amortized cost = \(1+1 = 2\).

  • POP

    • Potential change = \((|S|-1) - |S| = -1\).

    • Amortized cost = \(1+ (-1) = 0\).

  • MULTI-POP

    • Potential change = \((|S|-k) - |S| = -k\).

    • Amortized cost = \(k+ (-k) = 0\).

Amortized analysis: potential method

  •  Total amortized cost per operation \(\leq 2\).

  •  Total amortized cost for \(n\) operations is \(O(n)\).

  •  So average cost per operation is \(O(1)\).

Dynamic Table

Dynamic Table

Goal: Store items in a table (Example: hash table, binary heap etc.)

  • Two operations: INSERT and DELETE.

    • too many items inserted \(\implies\) expand table.

    • too many items deleted \(\implies\) contract table.

  • Requirement: If the table contains \(m\) items, then space = \(\Theta(m)\).

Suppose we are performing a sequence of \(n\) insert operations:

  • If there is a space in the table to insert, then the insertion cost is \(O(1)\).

  • If there is no space to insert, we need to expand the table, and then insert the element into the new table. This costs \(O(n)\) because,

    • We need to first copy all the elements from old table to new table.

    • Insert the element in the new table

Thus, an intermixed sequence of \(n\) INSERT and DELETE takes \(O(n^2)\) time.

Dynamic table: insert only

  •  When inserting into an empty table, allocate a table of capacity \(1\).

  •  When inserting into a full table, allocate a new table of twice the capacity and copy all items.

Cost model: Number of items written (due to insertion or copy).

Amortized analysis: aggregate method

  •  Let \(c_i\) denote the cost of \(i^{th}\) insertion.

    • \(c_i = i\) if \(i-1\) is an exact power of \(2\).

    • \(c_i = 1\) otherwise.

  •  The cost of \(n\) INSERT operations is \(\displaystyle\sum_{i=1}^n c_i\leq n + \displaystyle\sum_{j=0}^{\log{n}}2^j\leq n + 2n = 3n\).

Amortized analysis : accounting method

Insert: Charge \(3\) credits (use \(1\) credit to insert; save \(2\) with new item).
Invariant: \(2\) credits with each item in right half of table; none in left half.

  • Each newly inserted item gets \(2\) credits.

  • When table doubles from \(k\) to \(2k\), each of \(k/2\) items has \(2\) credits.

    • These \(k\) credits pay for the work needed to copy all \(k\) items.

    • now, all \(k\) items are in left half of the table (and have \(0\) credits).

  • In the similar manner, amortized cost per insert = \(3\).

  • Total actual cost of \(n\) operations \(\leq\) sum of amortized cost \(\leq 3n\).

Amortized analysis: potential method

Potential function: Let \(\Phi(D_i) = 2\times\mbox{size}(D_i)-\mbox{capacity}(D_i)\).

  • \(\Phi(D_0) = 0\).

  • \(\Phi(D_i)\geq 0\) for each \(D_i\).

Amortized costs:

  • Case \(0\) (first insertion)

    • Actual cost \(c_1 = 1\)

    • \(\Phi(D_1) - \Phi(D_0) = (2\times\mbox{size}(D_1)-\mbox{capacity}(D_1)) - (2\times\mbox{size}(D_0)-\mbox{capacity}(D_0)) = 1\).

    • Amortized cost = \(c_1 + \Phi(D_1)-\Phi(D_0) = 1 + 1 = 2\).

Amortized analysis: potential method

Potential function: Let \(\Phi(D_i) = 2\times\mbox{size}(D_i)-\mbox{capacity}(D_i)\).

  • \(\Phi(D_0) = 0\).

  • \(\Phi(D_i)\geq 0\) for each \(D_i\).

Amortized costs:

  • Case \(1\) (no array expansion)

    • Actual cost \(c_i=1\)

    • \(\Phi(D_i) - \Phi(D_{i-1}) = (2\times\mbox{size}(D_i)-\mbox{capacity}(D_i)) - (2\times\mbox{size}(D_{i-1})-\mbox{capacity}(D_{i-1})) = 2\)

    • Amortized cost = \(1+ 2 = 3\).

Amortized analysis: potential method

Potential function: Let \(\Phi(D_i) = 2\times\mbox{size}(D_i)-\mbox{capacity}(D_i)\).

  • \(\Phi(D_0) = 0\).

  • \(\Phi(D_i)\geq 0\) for each \(D_i\).

Amortized costs:

  • Case \(2\) (array expansion)

    • Actual cost \(c_i = 1 + \mbox{capacity}(D_{i-1})\)

    • \(\Phi(D_i) - \Phi(D_{i-1}) = (2\times\mbox{size}(D_i)-\mbox{capacity}(D_i)) - (2\times\mbox{size}(D_{i-1})-\mbox{capacity}(D_{i-1})) = 2 - \mbox{capacity}(D_{i-1})\)

    • Amortized cost = \(1+ \mbox{capacity}(D_{i-1}) + 2 - \mbox{capacity}(D_{i-1})= 3\).

Amortized analysis: potential method

  •  Total amortized cost per operation \(\leq 3\).

  •  Total amortized cost for \(n\) operations is \(O(n)\).

  •  So average cost per operation is \(O(1)\).
